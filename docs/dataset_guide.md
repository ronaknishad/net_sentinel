# Dataset Guide

## Primary dataset (not bundled): CIC-IDS2017
- Source: Canadian Institute for Cybersecurity (University of New Brunswick). Flow records produced with
  CICFlowMeter, with a `Label` column such as BENIGN, DoS, PortScan, FTP-Patator and so on.
- Size: the CSV release is hundreds of megabytes across several files, so it is **not downloaded
  automatically**. Check the source site for the current licence and citation requirements before using it.
- Suggested start: one day's file. The import limit is 200 MB per file and 2,000,000 rows.
- Place files in `datasets/` or upload them on the Dataset Management page.

## Bundled demonstration data
`ml/data/sample_synthetic_flows.csv` (3,015 rows) is **synthetic**. It is generated by `ml/synthetic.py`
from simple rules (see the module docstring), with deliberate label overlap, some blank and infinite
values and duplicated rows so the cleaning code is exercised. Scores on it describe the generator, not
real traffic. The application marks synthetic datasets and models wherever they are shown.

## Expected format
One flow per row, a header row, and a label column (auto-detected from `Label`, `Attack`,
`Attack_cat`, `Class`, `Traffic_Type`, or chosen manually). Header variants such as `Tot Fwd Pkts` and
`Total Fwd Packets` are matched automatically; spaces and case do not matter.

## Model input features (schema version 1.0)
| Feature | Meaning |
|---------|---------|
| destination_port | Destination port |
| protocol | IP protocol number (6 TCP, 17 UDP) |
| flow_duration | Duration in microseconds |
| total_fwd_packets, total_bwd_packets | Packets in each direction |
| total_fwd_bytes, total_bwd_bytes | Bytes in each direction |
| fwd_packet_length_mean, bwd_packet_length_mean | Mean packet length per direction |
| flow_bytes_per_s, flow_packets_per_s | Flow rates |
| flow_iat_mean | Mean inter-arrival time |
| syn_flag_count, ack_flag_count, rst_flag_count | TCP flag counts |

A dataset must supply at least 6 of these. Missing features are reported and left out of the model;
inference later requires exactly the features the model was trained with. If your headers differ, use the
explicit feature mapping on the Dataset Management page.

## Columns deliberately excluded
Flow IDs, row IDs, source and destination IP addresses, timestamps and source ports are never model
inputs. They would let a model memorise hosts or capture schedules rather than learn traffic behaviour.
Timestamps and flow IDs are kept only for display, and the timeline chart.

## Leakage assessment
- **Split first, learn second.** Imputation and scaling are inside scikit-learn pipelines fitted on the
  training split only.
- **Duplicates.** Identical rows (features and label) are removed before splitting, so a flow cannot
  appear in both training and test sets.
- **Identifiers and time** are excluded as described above.
- **Destination port is a known shortcut.** In many public datasets particular attacks target particular
  ports, so a model can lean on the port instead of behaviour. It is kept because it is a legitimate flow
  property, and it ranks among the top features in the synthetic example. Excluding features is not configurable in this version (see limitations), so treat
  accuracy on a single capture with caution.
- **Class imbalance** is handled with class weights during training only. The test split keeps the natural
  class mix.
- **Rare classes** (fewer than 10 samples) are excluded from training and listed on the Model Evaluation page.

## Data-quality handling
| Problem | Handling |
|---------|----------|
| Infinite values (for example rate on a zero-duration flow) | Replaced with missing, then imputed with the training median |
| Missing or non-numeric feature values | Counted in the report; imputed inside the pipeline |
| Rows with no label | Removed and counted |
| Rows with no valid feature value | Removed and counted |
| Duplicate rows | Removed and counted |
| Unreadable or invalid file | Rejected with a message; nothing is stored |
